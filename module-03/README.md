# Module 3: Running Jobs

## From files to jobs

You have logged in, made your own workspace, and organized an inherited project. Now it is time to run some code.

The Python examples are intentionally simple. You do **not** need to understand machine learning or PyTorch for this session. The Python script is the “payload” for the job. Our focus is on submitting it through Slurm, finding its output, and understanding what happened when something goes wrong.

<br>

## Learning focus

- Submit a simple batch job using Slurm.
- Use an interactive allocation to test a command.
- Read Slurm output files and distinguish application errors from scheduler messages.

<br>

## Activities

1. [Batch and interactive jobs](exercises/batch-and-interactive-jobs/README.md): inspect the workload, submit a working job, and try an interactive allocation.
2. [Diagnose and fix](exercises/diagnose-and-fix/README.md): read a traceback, fix an application error, and resubmit the job.

Follow Canvas for lesson order and assessment requirements. During a live workshop, pause between activities until your instructor asks you to continue.

The point for today is simple: run your code, read the output, fix errors, and try again.
